Shared Sonos core + pluggable board/UX units

Firmware reorganization plan — splitting one flat build into a reusable core with per-unit hardware & UX layers.
core = shared boards = hardware units = UX

Context

Today the firmware is one flat tree hard-wired to a single product: the round 2.1″ rotary CrowPanel (sonos-nest). A second unit is coming — the rectangular 2.8″ ES3C28P (sonos-sleep-machine) — with a completely different board stack and a different UX. More form factors are expected after that.

sonos-nest — current
  • ST7701 480×480 RGB-parallel
  • CST816 touch @0x15
  • EC11 rotary encoder + knob button
  • PCF8574 expander (power/reset/button)
sonos-sleep-machine — new deferred
  • ILI9341 240×320 4-wire SPI
  • FT6336G touch @0x38
  • no encoder · no expander
  • + microSD · mic · RGB-LED
Good news from exploration: the device-agnostic Sonos logic is already cleanly separated. sonos/*, library, player_state, settings, net/{wifi,ota} have zero includes from ui/ or hw/. The UI reaches core only through the mutex-guarded globals g_player/g_pending/g_zonesGen and the library::/sonos::/settings* APIs. The coupling that matters is concentrated in two files: main.cpp (mixes control logic with board bring-up) and ui/screens.cpp (round/rotary layout + encoder/knob input).

This pass: fully reorganize the existing nest firmware into a shared-core + per-board + per-unit layout, add per-unit PlatformIO envs, and stub out (compiles, does not implement) the es3c28p board and sleep_machine unit dirs. The real ILI9341/FT6336 driver and the sleep-machine UX are explicitly deferred. pio run -e nest stays green at every step; pio run -e sleep-machine must compile at the end to prove the seam.

Target layout

src/
  main.cpp            thin: playerStateInit → settingsInit → boardInit →
                      uiInit → albumArtInit → appBoot → appStartTasks
  core/               device-agnostic — compiled into EVERY env
    sonos/{didl,soap_client,ssdp}.{h,cpp}
    library · player_state · settings · album_art
    net/{wifi,ota}.{h,cpp}
    app.{h,cpp}       NEW — extracted controller (zone select, poll tasks)
    board.h           NEW — HAL contract every board implements
    unit.h            NEW — UX contract every unit implements
  boards/
    crowpanel_rotary/ display · touch · encoder · pcf8574 · board.cpp · pins.h
    es3c28p/          STUB — pins.h + board.cpp (ILI9341/FT6336 = TODO)
  units/
    sonos_nest/       screens + ui_scale (round/rotary)
    sleep_machine/    STUB — placeholder screen + ui_scale (240×320)
platformio.ini        per-unit envs via build_src_filter + -DUNIT_* / -DDEVICE_HOSTNAME

Key design decisions (validated)

  • build_src_filter — exclude-then-include. Setting the filter drops PlatformIO's implicit +<*>, so start with -<*> then add exactly one board + one unit. Two boardInit/uiInit definitions fail loudly at link — a good safety net.
  • Add -I src and rewrite ../foo.h cross-package includes as root-relative core/foo.h — the single biggest churn-reducer, done first.
  • No function renames. Keep backlightSet/encoderDelta/knobEvent/ knobPressed/knobDown/touchRead as the board.h contract — only relocate declarations. Encoder/knob return 0/None on touch-only boards.
  • Wire.begin() moves to boardInit() — today it's a hidden side effect of pcf8574Init(); the ES3C28P has no expander, so the board must own the bus.
  • Touch stays an LVGL pointer indev; encoder + knob stay pull-based (polled in uiTick). Registered inside boardInit() after lv_init().
  • app.cpp extraction pulls the zone statics, selectZone*, processPending, and the net/art/ui tasks out of main.cpp; exposes only appBoot() + appStartTasks().
  • OTA hostname → DEVICE_HOSTNAME macro, set per-env, so two units don't collide on sonos-nest.local.
  • Arduino_GFX stays pinned at v1.3.1 — confirmed it already ships Arduino_ESP32SPI + Arduino_ILI9341 alongside the ST7701 driver, so the second board needs no version bump. lib_deps stays in [env] (LDF chain mode skips uncompiled libs).

Migration order — build green at each step

  1. HTML plan doc + -I src. Generate this file; add -I src to [env]. build ✓
  2. Create src/core/, move the clean modules (sonos, library, player_state, settings, net/wifi, net/ota). Set the exclude-then-include filter; rewrite ../ includes root-relative. build ✓
  3. Move album_art.{h,cpp} → core/; fix its + screens.cpp includes. build ✓
  4. Add core/board.h + core/unit.h; relocate KnobEvent. Thin boards/crowpanel_rotary/board.cpp wraps the existing init sequence; main.cpp bring-up block becomes one boardInit(). build ✓
  5. Move hw/* → boards/crowpanel_rotary/, board_pins.h → pins.h. Move Wire.begin() into boardInit(). Fix bringup/phase1 includes. build ✓
  6. Extract core/app.cpp; move screens + ui_scale → units/sonos_nest/. main.cpp goes thin. last single-product checkpoint ✓
  7. Split envs. Rename to nest (final filter, -DUNIT_NEST, -DDEVICE_HOSTNAME); rebase bringup/phase1/ota. pio run -e nest ✓
  8. Stubs last. boards/es3c28p/ + units/sleep_machine/ + [env:sleep-machine]. pio run -e sleep-machine compiles; nest stays green.

platformio.ini env shape

[env]              ; memory_type qio_opi, 16MB, default_16MB.csv, lib_deps
build_flags = ... -I include -I src -DLV_CONF_INCLUDE_SIMPLE ...

[env:nest]
build_flags = ${env.build_flags} -DUNIT_NEST -DDEVICE_HOSTNAME=\"sonos-nest\"
build_src_filter = -<*> +<main.cpp> +<core/> +<boards/crowpanel_rotary/> +<units/sonos_nest/>

[env:sleep-machine]
build_flags = ${env.build_flags} -DUNIT_SLEEP -DDEVICE_HOSTNAME=\"sonos-sleep\"
build_src_filter = -<*> +<main.cpp> +<core/> +<boards/es3c28p/> +<units/sleep_machine/>

[env:nest-ota]    ; extends = env:nest, espota, upload_port = sonos-nest.local
